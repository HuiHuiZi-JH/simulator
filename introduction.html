MicroGrid
Simulatorwithout the hardware

A pure-Python Modbus TCP slave that impersonates a whole microgrid — solar inverter, battery, EV charger, building load, and revenue meter — so an energy management system can be exercised against realistic, controllable devices instead of a lab bench.

  • 5 device models
  • 0 third-party dependencies
  • 1 Hz physics tick
  • 32-bit signed · ×100 scaling
  • FC 3 read · FC 16 write

Architecture

Two threads, one shared state table

main.py starts a simulation thread and a server thread over a single devices_data dictionary, guarded by one lock. The simulation thread advances every device model once a second and writes the results into each device's register table. The server thread answers Modbus requests out of that same table — so a client always reads a coherent snapshot, and anything it writes becomes an input to the next tick.

  • Generation — reduces net import
  • Consumption — adds net import
  • Modbus TCP — reads and setpoint writes

Device models

Five models, each with its own physics

Every model exposes the same contract — a constructor taking its slice of device.json, and an update() returning a dictionary of named points. The simulation loop maps those names onto register offsets and drops them into the shared table.

PV Inverter

Generates

Follows a 24-hour irradiance curve, either interpolated from a CSV or synthesised as a sin² arc from 06:00 to 18:00 with ±5% noise. Output is clamped to whatever active-power limit the client has written, which is how curtailment gets tested.

Meter

Measures

Reads every other device each tick and computes the point of common coupling: consumption minus generation, with the battery counted on whichever side its sign puts it. It integrates that net figure on a monotonic clock into separate import and export registers, so the totals survive a long tick or a system clock change.

Protocol

A hand-written Modbus TCP server

The server speaks raw sockets — no pymodbus, no dependency tree at all. It frames MBAP headers itself, streams partial packets into a buffer until a full request arrives, and routes each one to a device by unit ID.

32-bit values across register pairs

Every point occupies two consecutive registers as a big-endian signed 32-bit integer, scaled by 100. That is why all offsets are even and why request quantities must be even too — an odd count would split a value in half.

Function codes

3 reads holding registers; 16 writes multiple. 6 is deliberately rejected with exception 1, because a single-register write cannot carry a 32-bit value. Bad addresses return exception 2, malformed frames exception 3.

Unit ID routing

Each device claims a unit ID from 1 to 247. On startup the loader validates them, and anything out of range or duplicated is replaced with the next free ID rather than shadowing another device.

Concurrent clients

Every accepted connection is handled on its own daemon thread. Reads and writes both take the shared lock, so a client polling registers 0–4 cannot observe half of one tick and half of the next.

Closing the loop. Three registers are inputs rather than outputs — the PV power limit, the battery setpoint, and the EV charge setpoint. Write one and the next tick reflects it, which is what makes the simulator useful for testing a controller instead of merely replaying data.

Configuration

One JSON file describes the site

config/device.json sets the simulated wall-clock start and lists the devices. Adding a second inverter or a third charger means adding an object, not touching code. 

{
  "start_time": "14:19",          // simulation begins at 14:19
  "Devices": [
    { "PV": [ {
        "DeviceKey":  "PV_01",
        "ratedPower": 100,
        "mode":       0,              // 0 = CSV curve, 1 = synthetic
        "csv_file":   "pv_curve.csv",
        "slave_id":   2
    } ] }
  ]
}

The simulated clock

Time starts at start_time and advances with real elapsed seconds, wrapping at midnight. One real second is one simulated second — curves play out in real time, so a full day takes a full day.

Power curves

pv_curve.csv and load_curve.csv hold 96 quarter-hour points covering 24 hours, as hour,kW pairs. Values between points are linearly interpolated.

Three log streams

Device state, protocol messages, and raw frame traffic each get their own rotating file under log/, with independent levels. When a client sees a value it did not expect, the traffic log has the bytes.

Running as a service

MicroGridSimulator.service is a systemd unit that restarts the simulator on failure and routes output to syslog. Update the paths inside it to match wherever the repository is checked out.

Getting started

Run it

There is nothing to install. Start the simulator from the repository root so the relative config paths resolve, then point any Modbus client at port 5021. 

python3 main.py

Read the meter. Unit 1, address 0, quantity 2 returns net active power as a signed 32-bit integer — divide by 100 for kW. A positive result means the site is importing from the grid; negative means it is exporting.
