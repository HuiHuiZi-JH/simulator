Deployment

Deploy manualMicroGrid Simulator on a host that never sees the source

A demo host is not a development machine. It gets a build, not a checkout: one file that installs the simulator, registers it with systemd and starts it — with no Python source left behind to read or edit.

  • One file · ~106 kB
  • No dependencies · standard library only
  • Modbus TCP 5021
  • Dashboard 8080
  • Installs to /opt/microgridsim

What ships

The release is one self-extracting file

dist/microgridsim-<version>-py<X.Y>.run is a shell script with a compressed payload stapled to the end of it. Run it as root and it unpacks itself into a temporary directory, installs, and cleans up after itself.

Inside the release

no .py files
FileWhat it is
microgridsim.pyzEvery module compiled to bytecode, zipped, with a shebang. This is the program.
config/device.json, the four day curves, log settings — the operator's files, edited on the host.
web/index.htmlThe dashboard. Browsers have to read it, so it is never secret.
MicroGridSimulator.serviceThe systemd unit, with @PREFIX@ and @PYTHON@ still to be filled in.
install.shThe four install steps, carried out for you.
PYTHON_VERSIONThe Python minor version this release was built for. Checked before anything is installed.

What is not in it

No .py sources, no tests, no design documents, no git history. The build compiles each module with compileall -o 2 — which also strips docstrings — deletes the sources, and rewrites the path recorded in each .pyc so a traceback on the host names the module and not your build machine.

What that does and does not buy

It stops browsing, not a determined reader. Bytecode is hidden, not encrypted: someone with root on the host can decompile it if they want to. Nothing that must stay secret belongs on a machine you do not control.

Procedure

Build, copy, install

Steps 1 and 2 happen on the development machine. Steps 3 onward happen on the host, as root — or rather, they happen for you: the installer runs them.

  1. Your machine  Build the release

    From the repository root. Omit the version and it takes one from git describe.

    cd /home/agent-ah/simulator/microgridsimulate
./deploy/build_release.sh v1.2

→ dist/microgridsim-v1.2-py3.12.run

  2. Your machine  Check the host's Python first

    Bytecode only loads on the minor version that compiled it. A release built on 3.12 runs on 3.12 and nowhere else. 

    ssh user@host python3 -V      # must match the py3.12 in the filename

    If it does not match, install a matching python3 on the host, or rebuild the release on a machine whose python3 matches it. The installer checks this itself and refuses before touching anything, so a mismatch costs you one sentence — not a service that restarts forever.

  3. Host  Copy it over and run it as root

    Two commands. Everything below happens inside the second one.

    scp dist/microgridsim-v1.2-py3.12.run user@host:~/
ssh user@host 'sudo ~/microgridsim-v1.2-py3.12.run'

  4. Host  The unit file goes into place

    Written to /lib/systemd/system/ with this install's prefix and python3 path substituted in, then systemd is told to pick it up. 

    # install.sh, on your behalf
sed s|@PREFIX@|/opt/microgridsim|g MicroGridSimulator.service \
    > /lib/systemd/system/MicroGridSimulator.service
systemctl daemon-reload

  5. Host  Enabled for boot, then started

    开机自动启动 — and a restart rather than a start, so running the installer again on a live host is an upgrade rather than an error.

    systemctl enable MicroGridSimulator.service
systemctl restart MicroGridSimulator.service
systemctl status MicroGridSimulator.service --no-pager

Installing somewhere other than /opt

Two environment variables, needed only if the site's layout differs. sudo -E passes them through. 

PREFIX=/srv/microgridsim   sudo -E ./microgridsim-v1.2-py3.12.run
UNIT_DIR=/etc/systemd/system sudo -E ./microgridsim-v1.2-py3.12.run

After the install

Where everything lives

The tree is root-only — 0700 directories and a 0400 archive. The service runs as root, and nothing else on the host needs to read it. 

/opt/microgridsim/
  microgridsim.pyz    the program — bytecode, 0400 root
  config/             device.json and the curves — edit here or from the dashboard
  web/index.html      the dashboard
  log/                simulation.log, message.log, modbus_traffic.log

WorkingDirectory in the unit is the prefix, and that matters. The program reads config/ by a relative path and takes web/ from the working directory when it runs out of the archive. Started by hand from somewhere else, it would look for its configuration in the wrong place.

Open 5021 and 8080 to whoever must reach the simulator, and nothing else. Both servers bind 0.0.0.0 and neither asks for a password — anyone who can reach the dashboard can change a setpoint.

Later

Upgrading and removing

Run a newer .run file on the same host. The archive and web/ are replaced; config/ is not.

What an upgrade keeps

Every file already in config/ stays as it is, and is named on the way past (keeping existing config/device.json). A site's settings and its uploaded curves survive. Only files that are missing are seeded from the release.

Which also means a corrected default curve will not overwrite one the site has already edited. Delete the file on the host first if you want the new one.

What it replaces

The bytecode archive, the dashboard, and the unit file — then the service is restarted, so the upgrade lands without a second command. 

scp dist/microgridsim-v1.3-py3.12.run user@host:~/
ssh user@host 'sudo ~/microgridsim-v1.3-py3.12.run'

If it does not start

The four things that actually go wrong

Symptom → cause → fix

journalctl -u MicroGridSimulator.service
What you seeWhat it meansWhat to do
Installer refuses: built for Python 3.12, but python3 is 3.11 Bytecode is tied to a Python minor version Install a matching python3, or rebuild the release on a machine that matches the host
bad magic number in the journal Same cause, reached the hard way — the host's python3 changed after installation Rebuild and reinstall against the host's current python3
Address already in use, then the service exits Something else holds 5021 or 8080 — often an older copy started by hand ss -ltnp | grep -E '5021|8080', stop that process, then systemctl restart
Browser shows a Not Found page that is not the dashboard Another application already owns port 8080 on that host — the web thread could not bind, and the simulation carried on without it, so the service still reads as active ss -ltnp | grep 8080 to see who has it, then set web_port in config/device.json to a free port the firewall already accepts and systemctl restart
Service runs, dashboard unreachable Firewall, not the simulator — it binds 0.0.0.0 Confirm with curl -s localhost:8080/api/state on the host, then open the port

The host needs no third-party packages. The release is standard library only, like the source it came from. If an install fails for a reason that is not in this table, the message from install.sh or the journal will say so in one line — it is written to.
